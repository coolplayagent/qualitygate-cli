# 真实试点收尾设计

> 日期：2026-09-17；对应 EVO-01–05 的真实使用验收；状态：执行输入待团队提供。

## 目标与边界

阶段 A–O 已给出试点的工程契约。收尾工作使用 manifest schema v10、
CLI 和外部签名流程，取得真实任务与独立人工观察。v10 按用户选择不要求
人工时薪或计价；这不改变真实试点须独立验收的边界。

| 编号 | 退出条件与反例 |
|---|---|
| C-01 | 在观察前选定 4 个独立缺陷修复和 4 个独立重构任务。每项有真实 issue/commit 来源、不可变基准、预先审定的目标与问题真值、任务契约和验证资产。历史回放、故障注入、同一任务的副本和 Agent 自拟真值不计入这 8 项。 |
| C-02 | 人工 owner、不同的独立 reviewer、仓库外持久归档与信任库已确认。固定环境、工具、缓存、Codex 两模型的推理强度和 32 个运行单元的交替顺序。缺输入时不能封存或开始计时；金额参数不是 v10 先决条件。 |
| C-03 | 对每个运行单元保留真实初始 full 报告。无观察的 v10 计划通过 `pilot seal`，输出进入持久归档；owner 对 `authorization-subject` 的精确主题签名。摘要只证明字节一致，不能替代身份或可信时间。 |
| C-04 | 七天内依序执行两模型×两流程，保留所有失败、超时、放弃和不完整尝试。每次尝试保留模型与执行记录、快照和完整报告；有可靠来源的费用可选记录。按 3 次/30 分钟及连续两次无进展停止，缺失样本留在分母。 |
| C-05 | 窗口结束后复核源文件、原始 Agent/进程/时钟日志、人工活跃时间及独立问题标签。只有八项非财务阈值均已知且满足、授权和报告均可重验时，才生成最终主题并由独立 reviewer 签接受；拒绝和未知保留原状态。 |
| C-06 | 本地获准的 Terra/Luna 是同一 Codex 产品的跨模型试点。EVO-03 的两种实际 Agent 产品目标单列为未完成；没有第二产品的授权、运行与可比数据时，不把本轮试点改称跨产品成功。 |

## 执行顺序与所有权

团队先给出 C-01/C-02 的真实内容；外部 harness 和 CLI 再完成 C-03/C-04；
独立 reviewer 完成 C-05。`domain::pilot` 只判定可序列化记录，
`config::pilot` 只验证受限归档字节，`application::pilot` 编排现有 CLI。
任务真实性、签名密钥、外部归档、原始模型路由与可信时间由团队掌握，
不能由 CLI 生成或由本地 fixture 推断。

## 验证与证据

A–O 的单元、集成、架构与 Skill 包回归证明上述机器契约可执行；
[准备度审计](../../docs/pilot-readiness.md)逐项记录真实输入的当前状态。
通过 `pilot seal`、启动授权、七天观察、`pilot acceptance-subject` 和
reviewer 签名形成的外部记录，才是 C-01–C-05 的退出证据。
未提供受信身份和任务时，保持待启动，不制造封存或验收成功记录。
