# 阶段 M：逐尝试模型证据与路由漂移审计

> 日期：2026-09-17；需求：EVO-05-04；状态：工程设计，真实试点未启动。

## 问题与交付契约

阶段 L 每个运行单元只有一份模型采集记录，但协议允许最多三次尝试。
如果重试时服务商更改了实际模型，一份记录无法表示各次尝试，更不能让 reviewer
定位失败或超时尝试的模型身份。阶段 M 保留原有请求配置比较口径，增加以下契约。

| 编号 | 要求与反例 |
|---|---|
| M-01 | 新计划使用 manifest schema v8，观察前的 plan seal 仍只绑定请求模型、推理档位、Agent/harness 身份和现有计划。v1–v7 的序列化、封存摘要和验收语义保持不变。v8 不允许运行单元级 `observation.model_evidence`；v1–v7 拒绝非空尝试级模型证据。 |
| M-02 | v8 每个已记录尝试可附一份有界 `attempt.model_evidence`，包括失败、超时、放弃和不完整尝试。缺记录可读入但令汇总 `complete=false`，不可生成最终接受主题。每份记录的工件和总量沿用 64 KiB／8 MiB 上限，重新核对受限路径、普通文件、长度、SHA-256 和严格 JSON 内容；不同尝试不能复用摘要。 |
| M-03 | 采集 JSON 包含与尝试一致的 `attempt_number`，并核对 assignment ID、封存的请求配置、Agent/harness 身份和窗口内且不晚于观察时间的采集时间。`reported` 必须有具体实际模型，`unknown` 必须有非空原因。运行单元 `cohort.actual_model` 只有在全部尝试记录完整且报告相同实际模型时才能填写；其他情形必须为 null。 |
| M-04 | 汇总逐尝试列出状态、请求和实际模型、未知原因、采集时间及归档摘要，并列出缺记录、未知身份、未观察单元和已报告的实际模型漂移。单元内至少两个不同的已报告实际模型是协议偏离，阻止最终接受；未知身份本身不等于漂移，也不冒充已报告身份。 |

## 所有权与可信边界

`domain::pilot` 定义可序列化契约、纯验证和审计；`config::pilot` 按现有归档
边界有界读取并比对模型文件；`application::pilot` 在所有 CLI 输出前复核。
模型文件及采集时钟来自外部 harness 声明，SHA-256 只绑定归档字节，不能认证
服务商路由或时钟。独立 reviewer 必须对照外部原始记录。不同请求配置或环境仍
分别分组，v8 摘要只评价请求配置的可比性，不能把已报告路由当作服务商证明。

## 验证与退出条件

单元测试覆盖失败／超时尝试、缺证据、未知身份、尝试号或计划身份失配、报告
模型漂移及旧版本拒绝新字段。CLI 测试覆盖真实文件、改动、越界、路径和符号
链接，以及旧 v7 完整封存 JSON 字节兼容。模板、Skill 包、文档和发布归档
一起更新。全套仓库门禁通过只证明工程契约；正式 8 项／7 天试点仍需真实来源、
签名、日志、人工复核与完整观察。
