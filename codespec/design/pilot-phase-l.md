# 阶段 L：逐运行单元绑定模型采集记录

> 日期：2026-09-17；需求：EVO-05-04；状态：工程设计，真实试点未启动。

## 交付契约

| 编号 | 要求与反例 |
|---|---|
| L-01 | 新计划使用 manifest schema v7。观察前仍封存请求模型、推理档位、Agent/harness 身份；观察记录中的模型采集信息不进入 plan seal。v1–v6 的序列化、封存摘要与验收语义保持不变。 |
| L-02 | 每个已观察运行单元提供一份有界 JSON 模型采集记录，清单声明相对路径、SHA-256、字节数和同一结构化内容。CLI 在汇总及最终验收前核对受限路径、普通文件、长度、摘要和 JSON 内容；记录缺失、变更、复用或身份不一致不能成为完整证据。 |
| L-03 | 采集记录必须绑定 assignment ID、Agent 版本、harness 摘要、请求模型、推理档位和采集时间，并与封存计划及观察时间相符。实际模型分为 `reported`（附具体标识）和 `unknown`（附原因）；与 assignment 的实际模型字段必须一致。未知是明确可接受的数据状态，不可伪装成已确认模型；缺采集记录仍为 incomplete。 |
| L-04 | 汇总逐单元列出请求模型、采集时间、报告的实际模型或未知原因、工件摘要与状态。只按请求配置比较，未知实际模型本身不阻断协议；报告的实际模型、采集时钟和提供者身份仍须由独立 reviewer 对照外部原始日志，归档摘要只证明文件未变。 |

## 所有权和边界

`domain::pilot` 定义严格可序列化记录、验证计划身份和纯汇总；`config::pilot` 有界读取并
比较归档 JSON；`application::pilot` 在输出前重新核对归档工件。每份记录至多 64 KiB，
整个记录清单至多 8 MiB。旧版本不允许新字段。没有读取或推断 Codex 私有日志格式，
因此 `reported` 是归档中的声称，不构成服务商签名或可信时间戳。

## 测试与退出条件

单元测试覆盖请求/实际模型失配、未知原因、采集时间、缺记录和旧版本兼容；CLI 测试覆盖
真实文件、摘要/内容变更、越界与符号链接。用上一安装版与新版比较同一 v6 计划的
完整封存 JSON 字节。质量门禁通过只证明工程契约，不能替代 8 个任务、7 天的真实观察。
