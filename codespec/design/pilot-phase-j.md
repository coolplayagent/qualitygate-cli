# 阶段 J：封存交替执行顺序并审计遵循情况

> 日期：2026-09-16；需求：EVO-05-01、EVO-05-03、EVO-05-04；状态：工程实现，真实试点未启动。

## 交付契约

| 编号 | 要求与反例 |
|---|---|
| J-01 | 新计划采用 manifest schema v5；`run_order` 在观察前列出每个 assignment ID，恰好一次。缺项、重复或未知 ID 拒绝封存；列表纳入 plan seal。 |
| J-02 | 顺序相邻运行单元必须交替使用 existing_tools 和 qualitygate。每个任务输入与请求模型都有一对流程；按任务类型和模型分层，既有流程先行与 qualitygate 先行的任务数差不超过 1。四个任务/层时须为 2:2。 |
| J-03 | 每个 v5 observation 可声明从 1 开始的 `start_sequence`，代表实际启动次序。非零、在计划范围内且不可重复。缺失序号为未完成顺序证据；与预定位置不同为协议偏离。偏离不能被其它指标或签名覆盖，最终验收主题要求 `protocol_ready=true`。 |
| J-04 | 汇总 `schedule_audit` 列出预定顺序、已声明实际顺序、缺失项和偏离项。它不从结束时间猜测启动次序；序号只是调用方声明，须由外部运行日志和 reviewer 复核。 |
| J-05 | v1–v4 不接受非空 `run_order` 或 `start_sequence`，原 JSON 与封存摘要逐字节兼容。v5 沿用 v2+ 总预算、v3+ 分层、v4+ 来源和十项接受阈值。 |

## 数据和所有权

`Manifest.run_order` 与 `Observation.start_sequence` 是严格反序列化的领域契约。
`domain::pilot::validation` 纯验证顺序、平衡和序号唯一性；`domain::pilot::schedule`
纯生成顺序审计；`domain::pilot::metrics` 将偏离或缺失加入协议限制。
计划序列属于 seal，观察序号不属于 seal，但由 manifest 摘要绑定最终验收主题。
无需新增进程、文件或网络读取。外部 harness 保留实际启动日志，复核人核对声明。

## 测试与完成判据

领域单元覆盖有效交替、分层平衡、缺失/重复/未知序号、改变已封存计划、实际顺序偏离
及旧版本拒绝新字段。CLI 集成覆盖 v5 封存、汇总偏离阻断和来源文件复验。
同一 v4 输入由上一安装版与新版封存必须得到完全相同的 JSON 字节。
工程门禁通过仅证明协议审计实现；真实启动日志、八项任务、签名与七天观察仍单独验收。
