# 阶段 I：绑定真实任务来源工件

> 日期：2026-09-16；需求：EVO-05-01、EVO-05-02、EVO-05-03；状态：工程实现，真实试点未启动。

## 交付契约

| 编号 | 要求与反例 |
|---|---|
| I-01 | 新计划采用 manifest schema v4，针对每个不同 `input_id` 预先声明一条任务来源：`kind` 为 issue 或 commit、可复核的 `source_id`、外部归档相对路径、SHA-256 摘要、字节数与选入时间。缺项、额外来源、重复输入、重复来源 ID/摘要/路径均拒绝封存。 |
| I-02 | 来源文件须为清单目录下的非符号链接常规文件，路径不能越界；每份 1–64 KiB、全部不超过 8 MiB，实际长度与摘要必须与声明一致。封存、启动授权主题、汇总及最终验收主题每次读取时重新核验；缺失、变更或越界为未完成，不能给出已验证来源的成功结果。 |
| I-03 | `selected_at` 必须非零且不晚于预声明的 `sealed_at`；这只是调用方时间声明，不能取代首次外部归档或可信时间。来源记录与 v3 的八项分层任务一一对应，32 个模型×流程 assignment 不能冒充 32 份独立来源。 |
| I-04 | v4 的来源清单与所有字段纳入原有 plan seal，观察后的来源 ID、摘要、路径或时间漂移使旧 seal、启动授权及最终验收主题失配；汇总展示每个独立输入的来源种类、ID、摘要与选入时间。 |
| I-05 | schema v1/v2/v3 继续保持原 JSON 和计划摘要；v4 沿用 v2/v3 的预算、分层、十项阈值与签名语义，不把新增来源当作新的收益指标。 |
| I-06 | 摘要验证只证明归档文件与声明相同，`source_id`、`kind`、选入时间及文件内容的真实性仍由 human owner/reviewer 对照外部 issue/commit、Git 历史和归档确认；工程 fixture 不算正式样本。 |

## 数据和所有权

`Manifest.sources` 是每个独立任务一条、严格反序列化的 `TaskSource` 清单；旧版本省略该字段。
`domain::pilot::validation` 纯校验版本、映射、唯一性、预算和时间并扩展 plan digest；
`domain::pilot::metrics` 纯展示来源审计。`config::pilot` 负责有界读取、路径限制和 SHA-256
校验；`application::pilot` 保持阻塞 I/O 不进入异步路径，并在返回前重新核对来源文件。
`interfaces`、签名 adapter 与 runner 无新所有权或网络能力。

## 测试与完成判据

领域单元覆盖有效来源、缺项、重复项、时间漂移、封存后改动与旧版本拒绝新字段；
`pilot_seal` CLI 集成覆盖真实临时文件、缺失/改动/符号链接/越界及汇总再验证。
同一 v3 输入由上一安装版与新版封存必须得到完全相同的 JSON 字节。
完整工程门禁通过只证明来源绑定实现；正式任务清单、来源真实性、外部授权和七天观察仍独立验收。
