# 阶段 K：基于初始报告审计修复预算与无进展停止

> 日期：2026-09-16；需求：EVO-03-03、EVO-05-01、EVO-05-03；状态：工程实现，真实试点未启动。

## 交付契约

| 编号 | 要求与反例 |
|---|---|
| K-01 | 新计划采用 manifest schema v6。每个 assignment 在观察前声明 `initial_report` 的相对路径、SHA-256 和字节数；`protocol.no_progress_limit` 为大于零且不超过最大尝试数。两个字段进入 plan seal。v1–v5 序列化与封存摘要保持不变。 |
| K-02 | CLI 封存和导出启动授权主题前，必须有界读取每份初始报告，核对常规文件、受限路径、长度、摘要、完整 full gate、初始快照和同一任务/策略/环境/工具/必需检查身份；汇总及最终主题重新读取。初始报告缺失、损坏或身份不符不能作为已验证基线。全部初始报告与尝试报告共享 64 MiB 读取预算。 |
| K-03 | 每次尝试的可验证进展采用阶段 B harness 的严格规则：完整、绑定的 full 报告中，错误诊断 `check_id:fingerprint` 和 gate blocker 的集合须为上一份已验证报告的真子集。blocker 须与独立检查状态重算值一致；换一个错误、数量不变或仅修改源码不重置无进展计数；缺失/不完整报告无可验证进展。记录报告摘要、前后债务数及判定。 |
| K-04 | 每个运行单元的全部尝试计入 `max_attempts` 与累计 `max_seconds`；超过上限、在连续 `no_progress_limit` 次无进展后继续尝试，均为协议偏离。审计保留超限尝试及成本，不从分母删除。失败/超时/放弃且未附报告按无可验证进展计；已声明完成却无报告、引用损坏或基线缺失为未完成。偏离/未完成使 `protocol_ready=false`，缺证使 `complete=false`。 |
| K-05 | 汇总 `attempt_audit` 按 assignment 展示基线、尝试、进展与预算/停止偏离。它不能证明 Agent 日志、计费或时间声明真实；外部 harness 与 reviewer 复核这些事实。旧版本不用新审计，也不能带入新字段。 |

## 数据和所有权

`Assignment.initial_report` 与 `Protocol.no_progress_limit` 是领域契约。
`domain::pilot::attempt_audit` 纯计算证据绑定、债务真子集、预算与停止审计；
`rows` 复用同一报告身份检查，避免汇总与审计出现不同验证口径。
`config::pilot` 负责受限读取初始报告与尝试报告，`application::pilot` 将阻塞读取留在
既有 worker，并在输出前复核初始工件。无新增网络、进程或不受限 I/O。
