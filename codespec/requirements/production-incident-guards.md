# 现网事故防护规格

目标是判断代码变更能否在交付前打破一条已知故障链。判断单位是一个可执行的约束，例如“配置超限后仍能读取上一份有效配置”。输入、观测者、反例和覆盖范围决定能作出的结论。研究核对日期为 2026-11-18，本仓生产源码基线为 385ce27。事故原文、样本来源和各次修复的因果链收录在[研究记录](../../knowledge/best-practices/engineering-standards/guides/production-incident-patterns.md)。

## 优先防护的五类问题

| 条款与约束 | 在哪里观测，怎样使检查失败 | 本项目现状与实证 | 剩余条件 |
| --- | --- | --- | --- |
| IG-13 异常终止与 core dump。无效请求应得到约定错误，进程应继续服务。 | 由仍存活的父进程观测子进程，记录信号、输入和崩溃前最后完成的任务。按需关联 ELF Build ID、符号、栈与受控转储。 | **扩展实测**。缺字段触发 SIGABRT，检查阻断；修复后输出拒绝结果。另用 GDB 转储并重新载入，栈定位到样例的业务分支。 | SIGSEGV、栈耗尽、abort、外部终止和 OOM kill 须依据实际信号及系统记录归因；转储收集器、符号和重启循环需平台验证。 |
| IG-14 内存泄漏。可释放的分配在路径结束后应释放。 | 用已知泄漏验证检测器工作，再运行被测负载。对持续可达的缓存、队列和引用链，记录预热、回收点、保留对象、上限和趋势。 | **扩展实测**。LSan 识别 4096 字节不可达分配；修复通过；漏插桩时为 incomplete。本仓另有 nightly ASan 作业，启用 detect_leaks=1，范围是原生单元测试。 | RSS 增长可能来自分配器或缓存；本实验未量化长时间运行、可达对象或未执行路径的保留量。 |
| IG-15 非堆资源泄漏。请求完成、失败或取消后，借出的资源须归还或回到有界池。 | 对 FD、套接字、线程、子进程、临时文件和连接池分别计数；在清理完成后与稳定基线比较，同时断言后续请求仍能获得资源。 | **扩展实测**。同一 Linux 进程连续 16 次走文件错误路径，FD 由 4 增至 20，修复后保持 4。 | 网络连接状态、取消后的回收期限、池配额、并发后台任务和其他平台句柄需各自的观测者。 |
| IG-16 边界。长度、计数、索引、容量及单位在生产者、校验器与消费者一致。 | 覆盖空、最小合法值、上限两侧、截断、长度声明与实际不符、加乘溢出。对原生内存访问补充 ASan，对解析预算还要在分配前检查。 | **扩展实测**覆盖长度 0、7、8、9、usize::MAX；独立约定检出把合法上限 8 错判为非法。IG-04、10、12 另有容量、计数与阈值回归。 | 本组长度实验未观测原生内存越界；跨语言 ABI、真实解析器及所有消费分支需对应平台和构建产物。 |
| IG-17 模块依赖必须无环。检查时须先约定节点是 owner、语言模块还是包。 | 从完整生产源码或构建清单提取有方向的依赖边并保留出处。直接互引、三节点闭环应失败，共用下游的 DAG 应通过。 | **现行策略覆盖顶层 Rust owner**。quality 检查从生产入口构图，包含来源文件、行号和摘要。实测两节点和三节点环均被识别，共享下游通过。同一 owner 内部两模块互引没有形成 owner 边。**规则实测**用 import-boundary 阻断事先约定的显式反向导入，等效的完整限定类型路径仍通过。**扩展实测**用 javac 检查 Java 具名模块，直接和三方环均阻断，无环通过，缺编译器为 incomplete。 | 约束具体业务模块时，须以模块身份重新提取边并运行检查。动态加载、生成源码、条件构建和反射须另列清单及适用配置。 |

资源与崩溃的原始观测、运行命令和局限见[原生实验](../test/production-incident-native.md)。Rust 模块反例及生产图范围见[架构与回归实证](../test/production-incident-regressions.md)，Java 模块的实验命令见[编译器扩展实证](../test/production-incident-models.md)。已有的 [ASan 驱动模板](../../templates/asan/README.md)适用于配置了插桩清单的 CMake/CTest 项目；本仓 CI 作业与项目模板各自拥有独立的构建和测试范围。[本仓 CI](../../.github/workflows/pr-checks.yml)

## 从其他故障链推导的条款

| 条款 | 项目可执行的检查与反例 | 防护状态及边界 |
| --- | --- | --- |
| IG-01 旧写入不能使活动版本倒退，清理不得删除仍在使用的数据。 | 在每个交错步骤检查版本与可读性；旧发布者准备后暂停，待新发布者提交并清理再恢复。 | **扩展实测**。30 种合法排列中缺陷版失败 10 种，修复后全过。实际存储的原子性、复制和故障重试待验证。 |
| IG-02 激活新分支的策略变更须容忍缺失或空字段。 | 通过应用的策略入口依次送入旧版、缺字段、显式空值、有效值，确认执行新分支并检查服务决策。 | **待接入**真实配置解析与消费者；IG-13 只验证最小缺字段样例。区域恢复负载要在发布平台验证。 |
| IG-03 新旧版本的写入、读取和回退均须兼容。 | 两版互写互读，强制异步消费完成才记录健康。保留旧快照，测试恢复后请求成功。 | **待接入**应用兼容性套件。真实晋级时机、快照可取回和最大回滚耗时需发布平台证据。 |
| IG-04 重复及超限配置不得覆盖最后有效配置。 | 生成端送出重复、低于上限、恰好上限和超限列表，检查消费者留下的活动状态。 | **扩展实测**。4 个用例中缺陷版失败 2 个，修复后全过。跨库实际查询和线上代理路径待验证。 |
| IG-05 单区失效时恢复所需依赖可用。 | 以区为单位移除拓扑节点，检查镜像、控制面、扩容依赖；在其他区验证能启动真实实例。 | **生产平台证据**。项目工具可检查已声明依赖图；拓扑新鲜度、备用容量和现场恢复须由演练确认。 |
| IG-06 耗时计算应容忍墙钟回拨。 | 注入可回拨时钟，在选择上游的入口断言耗时权重合法且仍能选择健康端点。 | **待接入**可控时钟与业务断言；时钟源和跨机时间语义依平台确定。 |
| IG-07 批量操作应维持分系统最低容量。 | 解析合法参数后计算操作后容量；测试恰到下限、低于下限、重复请求和局部完成。 | **待接入**运维工具的预检和模型；真实容量、速率限制是否生效需运行时观测。 |
| IG-08 错误路径须保留调用者约定的失败语义。 | 裸捕获作为源码线索；对显式捕获后吞错的例子，再从调用入口断言结果和状态。 | **规则实测**。裸捕获可定位；仅 warning 时仍可交付。显式处理后吞错与正常处理在这条规则上均无发现。语义检查仍需业务测试。 |
| IG-09 跨操作的先后和原子性约束须在不利调度下成立。 | 将准备、提交、失效等操作拆为可控步骤，每步检查读者可见状态。 | **扩展实测**限于 IG-01 的有限模型；真实线程内存序、锁顺序及调度空间另测。 |
| IG-10 聚合计数不得回绕、崩溃或被当作完整证据。 | 单份可表示，总和超界；保留已收集证据并阻断依赖。 | **现行回归**覆盖外部报告计数的合并。 |
| IG-11 独立输出的规范化路径必须唯一。 | 不同字符串指向同一路径时应在启动前拒绝；两条不同路径内容相同仍应分别处理。 | **现行回归**覆盖策略命令的当前和基线输出身份。 |
| IG-12 阈值须按原始命中数和总数判定。 | 对显示百分比一致而实际相差一次命中的输入，检查精确门槛两侧的裁决。 | **现行回归**覆盖本仓覆盖率报告路径。 |

模型的完整命令和阳性、阴性样本见[项目工具实验](../test/production-incident-models.md)；规则策略、三个修复提交与逐项重跑结果见[规则与回归实验](../test/production-incident-regressions.md)。

## 负载累积与恢复

| 条款与约束 | 可执行验证与实测 | 生产证据 |
| --- | --- | --- |
| IG-18 任务完成、取消或到期后，长期对象不得保留已失去业务用途的载荷。 | **扩展实测**。以弱引用观测 24 个任务。缺陷版队列已清空，16 个载荷仍被持有，共 4096 字节。修复后无存活载荷。项目测试应观察终态、保留路径、存活字节和合理的在途上限。 | 在真实并发、故障持续时间和预热条件下观测存活对象及队列年龄。分配器、GC 和服务吞吐需要各自的观测。 |
| IG-19 扩容前计算节点级资源成本，暂存新状态时须预留服务资源，更新失败后须保留可用配置并释放暂存资源。 | **扩展实测**。两条活动路由、三条待发布路由及两份服务预留。额度 7 可完成切换，额度 6 应在分配前拒绝，部分构建失败后旧版本仍可服务。 | 确认真实拓扑、线程与连接用量、并发冷启动以及控制面失效后的容量。不同平台的资源限制和继承方式需现场观测。 |
| IG-20 每个逻辑请求的实际后端调用数须有全链路约束，容量拒绝须保留明确的传播语义。 | **扩展实测**。独立重试层将持续暂态和容量拒绝都放大至 9 次。统一尝试额度后两者分别为 3 次和 1 次。还应验证允许恢复的暂态错误和永久失败对照。 | 真实系统再验证限流、带抖动退避、传播截止时间，以及依赖恢复时的有效吞吐和资源恢复速度。 |

两组以独立输入验证模型断言，工具无法形成报告时均为不完整。[滞留与重试实验](../test/production-incident-retention-and-retry.md) · [容量实验](../test/production-incident-capacity.md)

## 接入和采用判据

- 本仓现行策略启用一个内建规则 line-ending 和十项命令。上表的“现行回归”由现有测试命令执行。“扩展实测”和“规则实测”均在隔离策略运行，采用时要用目标项目真实入口及独立反例再次验证。[项目策略](../../qualitygate.yaml)
- 语法问题可用已支持的规则表达。需要执行程序、观测资源或构建语言模块图时，用 checks[].argv 启动项目工具，声明超时、版本探针、输入和必需报告。逐测试结果用 JUnit 或 diagnostics，定位的静态诊断可用 SARIF。多个规则确实复用同一事实时再考虑 V4；当前版本的工具事实为 Rust 函数指标及克隆对。[扩展契约](../design/tool-facts-and-assertions.md)
- 评审一项防护时应能回答三件事：缺陷样例能否稳定产生预期违规，修复样例能否通过，观测者失效时能否识别证据缺口。保存构建和输入身份、执行范围、命令、退出状态及报告。必需检查完整且有阻断违规时退出 1，完整通过为 0，缺报告、工具超时或基线不符为 2。每个实验应保留自身结论及尚未覆盖的环境；生产有效性由部署观测和演练独立验收。
