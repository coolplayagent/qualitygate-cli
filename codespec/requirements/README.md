# Requirements

The [clean contract maintenance supplement](clean-contracts.md) binds the
Clean Architecture/DRY/SOLID audit to compatibility and executable evidence.
The [Skill guidance supplement](skill-guidance.md) binds mode routing, four
design-review cards and source-bound instruction adoption to distinct package,
CLI and behavioral evidence.
The [Skill and rule boundary supplement](skill-rule-boundaries.md) binds syntax
counterexamples, policy authority, delivery scope, runtime/package preservation
and caller-selected pilot controls to their actual evidence limits.

This directory is governed by `codespec/codespec-map.yaml`. Update its map entry through `relay-knowledge map directory` and keep reviewed source material within the declared content scope.

The normative product contract is [qualitygate-cli requirements](qualitygate-cli.md).
Focused requirement documents refine that contract without replacing it.

The [tool facts and composable assertions SPEC](tool-facts-and-assertions.md)
defines TFA-01–TFA-08 contracts for external-tool facts, finite typed V4
assertions, candidate adapters and a second Bazel entry point in the same Cargo
package. Its first-stage development implementation and requirement-to-test
evidence are recorded in the specification; release and production adoption
remain separate from implementation verification. V1–V3 retain their contracts.

The [issue #4 requirement-to-test matrix](../../docs/en/02-reference/04-policy-task-and-signed-evidence.md)
tracks dynamic categories, evidence-linked candidates, protected validation,
independent approval, versioned inheritance and longitudinal effectiveness.
The [large repository contract](../../docs/en/01-user-guide/02-snapshots-and-check-workflow.md) defines
bounded parallel execution and reproducible performance evidence.

[File contracts](../../docs/en/02-reference/02-rules.md) and
[diagnostic ratchets](../../docs/en/02-reference/03-projects-and-tool-reports.md) define instruction
inventory and historical diagnostic growth requirements with executable
requirement-to-test mappings.

[Test effectiveness](../../docs/en/02-reference/02-rules.md) specifies explicit per-file
assertion counterexamples and paired snapshot evidence. [Custom rules](../../docs/en/02-reference/02-rules.md)
cover required text and minimum triggered entity counts under REQUIREMENTS §11.

The [cross-agent acceptance evolution SPEC](agent-acceptance-evolution.md)
defines the research-backed EVO-01–EVO-05 requirements for task-specific
acceptance, agent repair feedback, cross-agent rechecks, failure-driven rule
evolution and real-pilot benefit/cost measurement. It is a requirements draft;
existing implementation foundations remain separate from pending delivery and
pilot evidence under REQUIREMENTS §12.

The [pilot design and closeout conditions](../design/pilot.md) connect EVO-01–EVO-05
to the real-task inputs, pre-observation seal, external owner authorization and
independent reviewer decision. The [version guide](../design/pilot.md#版本与证据导航)
identifies which evidence and thresholds apply to each manifest.
