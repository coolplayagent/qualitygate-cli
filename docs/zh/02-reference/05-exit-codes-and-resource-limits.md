# 退出码与资源限制

[English](../../en/02-reference/05-exit-codes-and-resource-limits.md) · [本卷目录](README.md)

## 退出码

| 代码 | 含义 | 解释要求 |
| --- | --- | --- |
| `0` | 选中范围完整通过 | 同时保留范围、快照、策略、warning 与证据边界。 |
| `1` | 执行完整但存在阻塞违规 | 修复或取得授权的策略决定，不能静默削弱检查。 |
| `2` | 验证未完成 | 补齐前置条件或证据后重跑，不能宣称通过。 |

完整性与决策彼此独立：检查可以完整执行并因发现违规而失败。进程错误、超时、报告缺失、能力不支持、
输入过期或必需检查未执行都产生 incomplete。warning 过滤只改变展示，不改变 gate 计算。

## 默认快照边界

默认获取范围最多 100,000 个文件、每棵树 256 MiB 总内容、单文件 2 MiB、4 个读取 worker 和 120 秒。
Git 对象通常按最多 4 MiB 与 1,024 个对象分批；显式允许的更大文件单独成批。调用方参数为：

- `--snapshot-max-mib`：1–1024；
- `--snapshot-max-file-mib`：1–8，默认 2，独立于总预算；允许的大文件单独成批，最多 8 MiB，进程输出仍限 16 MiB；
- `--snapshot-jobs`：1–16；
- `--snapshot-timeout-secs`：1–3600。

每个进程流最多捕获 16 MiB。各适配器与规则还分别限制报告字节、文件数、源码行、诊断数、解析工作、
子进程时间与并发。有效报告会记录触发的限制。提高调用方预算不会授权更宽路径或更弱策略。

## 失败边界

路径限制拒绝目录穿越和符号链接逃逸。Git 冲突、submodule、特殊文件、对象不匹配、执行期间源码变化，
以及文本场景中的非法 UTF-8 都会失败关闭。网络与环境访问由明确适配器负责；缺少凭据或工具不可用
属于证据缺口。

单元、集成、live producer、Miri 与 ASan 结果必须分别解释。fixture 通过只覆盖其代表形态；真实仓库、
平台、网络和人工审核假设在独立验证前始终可见。
