# 退出码与资源限制

[English](../../en/02-reference/05-exit-codes-and-resource-limits.md) · [本卷目录](README.md)

## 退出码

| 代码 | 含义 | 解释要求 |
| --- | --- | --- |
| `0` | 选中范围完整通过 | 同时保留范围、快照、策略、warning 与证据边界。 |
| `1` | 执行完整但存在阻塞违规 | 修复或取得授权的策略决定，不能静默削弱检查。 |
| `2` | 验证未完成 | 补齐前置条件或证据后重跑，不能宣称通过。 |

完整性与决策彼此独立：检查可以完整执行并因发现违规而失败。进程错误、超时、报告缺失、能力不支持、
输入过期或必需检查未执行都产生 incomplete。warning 过滤只改变展示，不改变 gate 计算。

## 默认快照边界

YAML 策略、任务、项目规则、验证套件、打包规则和外部策略信任输入在解析前限于 1 MiB。
共享预检把展开量限制为 100,000 个访问值（包含映射键与标签名）、4 MiB UTF-8 字符串内容，
以及根值之下最多 64 层。每次别名引用都重新计量，在构造 YAML Value 或类型化集合前拒绝超限；
引号内类似别名的文本仍为普通内容。这些是确定的输入预算，不是进程内存或实际耗时保证。
项目规则继续保留额外的 50,000 节点形状限制。配置或任务超限产生未完成，`rules validate`
报告 YAML 规则无效，生成操作拒绝发布；原始输入保留，可修复后复验。

默认获取范围最多 100,000 个文件、每棵树 256 MiB 总内容、单文件 2 MiB、4 个读取 worker 和 120 秒。
Git 对象通常按最多 4 MiB 与 1,024 个对象分批；显式允许的更大文件单独成批。调用方参数为：

- `--snapshot-max-mib`：1–1024；
- `--snapshot-max-file-mib`：1–8，默认 2，独立于总预算；允许的大文件单独成批，最多 8 MiB，进程输出仍限 16 MiB；
- `--snapshot-jobs`：1–16；
- `--snapshot-timeout-secs`：1–3600。

每个进程流最多捕获 16 MiB。各适配器与规则还分别限制报告字节、文件数、源码行、诊断数、解析工作、
子进程时间与并发。有效报告会记录触发的限制。提高调用方预算不会授权更宽路径或更弱策略。

可执行文件身份只接受普通文件，包括指向普通文件的符号链接。打开前检查类型与大小，打开后再次
核验句柄，再计算摘要；已存在的命名管道、套接字和目录不能提供可执行证据。生产工具限制为
256 MiB；Qualitygate 执行器允许 1 GiB，以容纳开发调试信息。摘要计算在读取之间检查 30 秒预算。
此检查不防御恶意文件系统替换竞态，也不保证操作系统文件调用能按时返回。

配置读取与仓库发现同样在打开前拒绝特殊文件，并复核打开后的句柄。配置读取限制为 1 MiB，
读取期间增长也不能绕过限制；发现阶段保持单个输入 2 MiB、累计 12 MiB 的限制。
配置文件或根目录/嵌套目录的 `.gitignore` 是命名管道时返回未完成，不阻塞或发布初始化候选。
已存在但不可读的输入不会被当作策略缺失。

XML 报告、Maven/项目模型、兼容性证据和 Maven 发现限制元素深度为 32、树节点为 100,000、
每个元素属性为 1,024、整个文档属性为 100,000。根元素、文档根节点和命名空间声明分别计入
对应限制。迭代 token 预检在递归树解析与重复属性比较之前检查深度和属性预算；注释、CDATA、
处理指令或属性值中的字面属性文本不计入属性数量。调用方字节限制和格式专属 DTD 处理继续适用。
执行证据超限保持未完成并保留已采集的原始产物；建议性发现记录清单缺口，不重写已有策略。

命名空间继承展开与名称查找共享每个文档 10,000,000 个工作单位。对每个元素，令 `P` 为祖先
声明数（包括被遮蔽的前缀），`D` 为本元素声明数，`S = P + D`，`L` 为元素名称加带前缀属性名称
的数量。预检计入 `S * L`，当 `D > 0` 时再计入 `P * S`。关闭元素恢复父作用域但不返还预算。
这种保守计数限制命名空间放大，不是实际耗时预测，也不替代其他 XML 限制。

内置规则资产的所有包共享 256 个文件、1 MiB 的限制，边界值可用。
字节预算按实际读取量累计；文件增长或普通文件的元数据低报长度，也不能绕过总量限制。
每次最多读取剩余额度加一个用于检测超限的字节；超限在 YAML 解析前使目录加载未完成。
允许资产符号链接（包括 Bazel runfiles）指向普通文件；打开前及打开后均检查类型和大小。

## 诊断输出

每项检查最多保留 10,000 条诊断，诊断数组的 UTF-8 紧凑 JSON 最多 8 MiB，包括字符串转义和复验命令。
项目规则 v1/v2/v3 的文件清单、固定断言、依赖违规和表达式共享同一额度；追加记录前先计算字节。
应用层在阻塞工作池中绑定复验命令时再次检查额度。

超限使相应检查保持未完成，保留已收集的诊断前缀。`metadata.diagnostic_output` 记录限制、阶段和
保留数量，不宣称已统计全部省略的违规。先前的超时或执行缺口原因仍然保留。可缩小检查范围或精简
重复的修复文案；处理违规后应重新验证原有范围。策略授权和必需检查语义保持有效。
条款覆盖使用施加输出限制后的最终检查结果；诊断输出缺口对应的条款仍为待完成。

## 失败边界

路径限制拒绝目录穿越和符号链接逃逸。Git 冲突、submodule、特殊文件、对象不匹配、执行期间源码变化，
以及文本场景中的非法 UTF-8 都会失败关闭。网络与环境访问由明确适配器负责；缺少凭据或工具不可用
属于证据缺口。

单元、集成、live producer、Miri 与 ASan 结果必须分别解释。fixture 通过只覆盖其代表形态；真实仓库、
平台、网络和人工审核假设在独立验证前始终可见。

Doctor 退出 `0` 仅表示请求的 `scope: preflight` 通过；受阻或未完成退出 `2`，
不产生交付结论。见[运行时与预检](06-runtime-and-preflight.md)。
