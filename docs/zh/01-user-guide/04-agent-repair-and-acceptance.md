# Agent 修复与验收

[English](../../en/01-user-guide/04-agent-repair-and-acceptance.md) · [本卷目录](README.md)

`check --feedback` 从完整报告投影一份有界修复反馈，包含稳定诊断 ID、位置、证据引用、限制、
复验参数、待执行交付检查和原报告身份。它不会隐藏未完成状态，也不授权修改策略。

外层 harness 应保持修复循环有限：

1. 固定并保存初始快照、策略、任务和 full 报告。
2. 只向 Agent 提供相关反馈与获准源码范围。
3. 记录每次提案和尝试，包括失败与超时。
4. 使用相同权威输入复查产出的工作区。
5. 在成功、次数或时间耗尽、连续无进展或前置条件不可修复时停止。
6. 对实际组合后的最终快照执行无路径过滤的 full 检查。

重试次数与总耗时由 harness 管理。Agent 启动前预算耗尽、Agent 超时、命令失败和证据缺失必须保持
不同状态。修复不能关闭必需规则、降低严重级别、修改受信策略或伪造人工批准。

任务契约声明可观察验收项和验证方法，只能叠加仓库策略，不能削弱它。命令式验收必须证明目标
测试确实执行；零测试不能算通过。人工验收需要调用方控制的 trust store，以及与任务、快照、
策略、验收项、有效期和 reviewer scope 绑定的外部签名记录。

签名的 Agent provenance 可认证所声明的变换历史，但不能证明语义正确。Git trailer 可把声明关联到
实际修改测试的提交；它们是证据绑定，不替代执行。最终 gate 仍是选中快照和已配置检查的权威结果。
