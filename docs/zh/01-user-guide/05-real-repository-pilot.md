# 真实仓库试点

[English](../../en/01-user-guide/05-real-repository-pilot.md) · [本卷目录](README.md)

真实试点把仓库收益与 fixture、CI 工程证据分开。自动测试只能证明机制按契约工作，不能替代人工
确认的拦截率、误报率、修复收益或审查节省。

## 当前 v10 契约

新试点使用 `templates/pilot/observation-v10.json`。观察前需声明八个独立输入（四个缺陷修复、
四个重构）、两个模型组、existing-tools 与 Qualitygate 两种流程、交替执行顺序、任务来源工件、
每个 assignment 的初始 full 报告，以及有界的尝试次数、耗时与无进展停止规则。两个模型乘两种
流程形成 32 个运行单元。

每次尝试（包括失败与超时）都需要摘要校验的模型采集和执行回执。请求模型与报告模型分别保存，
无法获知实际路由时明确记为 unknown。回执绑定 harness 身份、起止时间声明、状态、快照和报告。
摘要不能认证服务商或时钟，因此独立复核仍需原始日志。

v10 明确不要求价格、币种、人工时薪或金额上限。最终主题评估八项非财务阈值：检测、误报、修复、
必需检查完成率、复核覆盖率、匹配输入、审查时间下降和 full 检查 P95 比率。已有 v1–v9 记录继续
遵循各自版本化的预算与阈值语义。

## 证据顺序

1. 外部 owner 选择真实任务、不可变源码、受信策略、任务契约、reviewer 和持久证据归档。
2. 在观察开始前用 `pilot seal` 封存完整计划。
3. `pilot authorization-subject` 生成精确主题，由 human owner 在外部 DSSE/Ed25519 信任系统签名。
4. 两种流程在声明窗口内按可比条件运行，所有尝试、省略、未完成检查和人工复核都进入记录。
5. `pilot acceptance-subject` 评估封存证据，由不同 reviewer 签署接受或拒绝。
6. `pilot summarize` 只验证给定记录，不改变策略，也不补造缺失指标。

缺少任务、reviewer、外部信任、持久归档、初始报告、观察或签名时，试点尚未开始或尚未完成。
缺失数据必须使用 null 并说明原因，不能补零。历史回放与受控 fixture 只是工程证据，不进入真实试点
分母。
